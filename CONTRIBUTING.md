# Contributing to NewChoBo Harness

NewChoBo Harness is developed in a public repository. Treat source files, commit messages, branch/tag names, Issues, Pull Requests, reviews/comments, workflow logs/artifacts, releases, examples, fixtures, generated outputs, and package/documentation metadata as public disclosure surfaces.

**If information is not clearly safe for public disclosure, do not post it here.**

The canonical rule is `protocol/public-information-boundary` in `standard/protocols/public-information-boundary.md`.

Do not submit credentials/secrets, private consumer/project/customer identities, private repository or automation coordinates, private operational evidence, unpublished private-domain material, raw private prompts/transcripts, or personal/sensitive data that is not intentionally public.

Prefer synthetic/minimized reproductions. Private evidence may motivate a contribution, but the public Issue/PR should contain only the generalized public-safe finding needed to evaluate the shared change.

## Material contribution flow

1. establish goal, scope, ownership, and current base;
2. implement on a candidate/topic branch;
3. run applicable validation and Worker self-check;
4. freeze exact candidate identity;
5. obtain producer-distinct PRE_ADOPTION_REVIEW;
6. address material findings;
7. integrate only the exact reviewed candidate under applicable authority;
8. validate effect after adoption when material.

Do not directly edit `main` to bypass the candidate/review lifecycle. Public Issues are durable public work records, not private incident or escalation channels.

For security-sensitive reports that cannot be safely disclosed publicly, follow `SECURITY.md` rather than posting sensitive material in an Issue or PR.
